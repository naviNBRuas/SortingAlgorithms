# Changelog

All notable changes to this project will be documented in this file.

## [1.1.0] - 2026-11-19
### Added
- 28 new algorithms (56 total): Ford–Johnson merge-insertion, library, Cartesian-tree, bottom-up and ternary heap, enumeration, permutation sorts and the pairwise network, plus circle, exchange, slow, bozo, quick-sort Hoare / 3-way / dual-pivot, double selection, bingo, tournament, weak-heap, Ciura-gap Shell, AVL tree sort, in-place and bottom-up merge, MSD radix, American flag, flash and sleep sorts, Batcher odd-even merge sort.
- Animated GIF for every algorithm plus a multi-algorithm `race.gif`, rendered from real traces with Pillow.
- `REPORT.md`: benchmark study (comparisons, writes, runtime, adaptivity, fitted exponents) with reproducible scripts in `benchmarks/`.
- Registry-driven metadata; README catalogue and gallery are generated by `scripts/build_docs.py`.
- Stability, sorting-network (0-1 principle), integer-key and docs-consistency tests; GitHub Actions CI.

### Changed
- Python core rewritten around an instrumented `Tracked` array: exact comparison/write counts and traces without per-algorithm boilerplate.
- Faithful implementations replace surrogates (smooth sort is now a real Leonardo-heap sort; TimSort implements run detection, minrun and merge-collapse invariants).
- Corrected stability claims (bubble, cocktail, odd-even and gnome sorts are stable).

### Languages
- Every one of the 56 algorithms now exists in Python, C, C++, Java, Go, Rust, x86-64 assembly, raw machine code and COBOL.
- New `kernels/`: each algorithm is written once as a restricted executable Python "kernel", verified natively, then transpiled by `kernels/generate.py` into C, C++, Java, Go, Rust, COBOL and x86-64 assembly. C, Go and Rust sources are now generated (replacing the previous hand-written, partly simplified ports; the full TimSort and smoothsort now exist in every language).
- New `machine-code/`: 56 self-contained, position-independent raw x86-64 images (about 37 KB) built from the assembly, with a loader test that runs each from executable memory.
- New `cobol/`: 56 GnuCOBOL programs plus a test driver, verified with GnuCOBOL 3.2.0 (including a `-debug` run with runtime subscript checks).
- C++ is header-only C++17; Java has one class per algorithm.

### Assembly
- The other 28 algorithms (those without hand-written assembly) are produced by the kernel compiler (`kernels/backends/x86.py`) into `assembly/generated/` and are labelled as compiler output.
- All 28 assembly sorts are now genuine hand-written assembly (GNU `as`, Intel syntax). Previously 20 of 28 were 6-line stubs that jumped into C. No libc is used: scratch memory comes from raw `mmap`/`munmap` syscalls.
- New `assembly/Makefile` with `test`, `freestanding` (links with `-nostdlib -static`) and `memcheck` (Valgrind) targets and a C test harness.

### Fixed
- C: `heap_sort` had an off-by-one and `smooth_sort` read out of bounds; `bitonic_sort` in C, Go and Rust was wrong for non-power-of-two lengths. All fixed, found by the new per-language test suites.
- Go/Rust `smooth_sort` was a heap-sort stand-in; now a real Leonardo-heap implementation.
- Go: duplicate `partition` symbol broke the build. Rust: `lib.rs` exported only 6 of 28 modules, so the demo did not compile. Python: stray diff markers in `__main__.py`.
- Removed tracked build artifacts (`*.o`, `libsort.a`, binaries) from version control.
